Technical & Functional Approach Document
Generic Workflow Engine System
SWCS 2.0 — Invest Uttarakhand
Kisi bhi service ka workflow — admin se configure karo, automatically sab roles ka dashboard, forms, aur actions handle ho jaayenge. Ek baar system bana lo, har nayi service sirf configuration se add ho jaayegi.
📅 March 2026 📌 Version 1.0 🏛 Invest Uttarakhand — SWCS 2.0 👥 For: Technical Manager · Functional Manager
Section 1 — Vision
Hum Kya Bana Rahe Hain?
Ek Generic Workflow Engine — jisme admin ek baar kisi bhi service ka workflow configure kare (kaun kaun se steps, roles, SLA, actions), aur uske baad applicant se lekar approval tak ka poora process automatically handle ho jaaye. Frontend ka ek bhi page kisi specific service ke liye hardcode nahi hoga.
⚙️
Pillar 1: Workflow Configurator
Admin panel se kisi bhi service ke workflow steps, roles, SLA, actions define karo. Config DB mein store hoti hai.
📝
Pillar 2: Form Builder
Applicant form bhi aur Department (processing) form bhi — dono FormBuilder se bante hain. Har step pe alag form.
⚡
Pillar 3: Runtime Engine
Jab applicant submit karta hai, engine automatically workflow start karta hai aur har action pe next step decide karta hai.
🖥️
Pillar 4: Generic Dashboard
Har role ka ek common dashboard — login ke baad role dekh ke automatically sahi applications dikhti hain.

Section 5 — Backend Architecture
New Backend Modules & APIs
3 naye NestJS modules banana hai. Ye existing modules se alag aur independent rahenge.
MODULE 1 apps/backend/src/modules/wf-engine/
POST
/wf-engine/start
Application submit hone ke baad yahan call hota hai. Config padh ke instance create karta hai Step 1 ke saath. SLA timer shuru hota hai.
POST
/wf-engine/action
Officer action leta hai (FORWARD/APPROVE/REJECT etc). Engine transition validate karta hai → instance update karta hai → log entry karta hai.
GET
/wf-engine/inbox?roleId=7&districtId=5
Is role ki aur is district ki pending applications return karta hai. Dashboard ke liye main API.
GET
/wf-engine/application/:submissionId
Ek application ki detail — form data, current step, allowed actions, timeline. Frontend is ek API se sab render karta hai.
GET
/wf-engine/timeline/:submissionId
Application ki poori history — kab kaunse officer ne kya action liya, remarks, form data.
GET
/wf-engine/forward-preview
Forward karne se pehle — kaunse officers available hain next role mein us district mein. Dropdown ke liye.
MODULE 2 apps/backend/src/modules/dept-officer/
POST
/dept-officer/create
Admin naaya department officer create karta hai. Users table mein entry + t_dept_officers table mein entry. Login credentials generate.
GET
/dept-officer/list?deptId=1&roleId=7
Department ke sab officers ki list. Filter by role, district, status.
PATCH
/dept-officer/:id
Officer ki details update — role change, district change, active/inactive.
MODULE 3 apps/backend/src/modules/wf-sla-cron/
CRON
Every 1 hour — SLA Breach Check
Sab instances check karta hai jahan sla_due_at pass ho gayi. Escalation rules ke hisaab se notify ya reassign karta hai.

Section 9 — Key Concept
System Generic Kaise Hai? Nayi Service Add Karna
Ek nayi service ke liye koi naya code nahi likhna. Sirf configuration aur form banana hai.
# Kya Karna Hai Kahan Karna Hai Code Change?
1 Service register karo (name, ID, dept) Service Master (admin panel) ❌ Nahi
2 Applicant Form banao (fields, validations) Form Builder (admin panel) ❌ Nahi
3 Processing Forms banao (har step ke liye) Form Builder (admin panel) ❌ Nahi
4 Workflow steps configure karo (roles, SLA, actions) Workflow Configurator (admin panel) ❌ Nahi
5 Workflow publish karo Workflow Configurator — Status: PUBLISHED ❌ Nahi
6 ✅ Done — Service live hai Applicant apply kar sakta hai, workflow chalu hoga ❌ Bilkul Nahi
